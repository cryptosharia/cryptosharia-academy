# VPS staging deployment

Build from the reviewed commit: `docker build -t cryptosharia-academy:staging-$(git rev-parse --short HEAD) .`. Replace the Compose image tag with the SHA tag before deploying. Create the external `cryptosharia_proxy` network separately and proxy HTTPS to `cryptosharia-academy-staging:3000` with Nginx Proxy Manager. Provide `ORIGIN` and, while the existing upload integration remains in use, `BLOB_READ_WRITE_TOKEN` in protected `.env.staging`. Health checks liveness only.

Firebase configuration is static public build configuration: `PUBLIC_ACADEMY_ENABLED`, `PUBLIC_FIREBASE_MODE`, `PUBLIC_FIREBASE_API_KEY`, `PUBLIC_FIREBASE_AUTH_DOMAIN`, `PUBLIC_FIREBASE_PROJECT_ID`, `PUBLIC_FIREBASE_MESSAGING_SENDER_ID`, `PUBLIC_FIREBASE_APP_ID`, `PUBLIC_FIREBASE_AUTH_EMULATOR_URL`, `PUBLIC_FIREBASE_FIRESTORE_EMULATOR_URL`. These values are exposed to clients and must never be secrets. Pass any required values as `docker build --build-arg PUBLIC_NAME=value` for the listed public names. These values are embedded in the client bundle and image; never pass secrets as build arguments. Do not place credentials in the build context.

Firebase Auth and Firestore remain dependencies. The existing Vercel Blob client upload and server token exchange remain in place and are an explicit cutover blocker: export and verify existing data, implement and test an alternative, then migrate references before retiring Blob. No self-hosted storage migration is included. Supabase and the CryptoSharia API are not direct dependencies found in this repository. The default build retains adapter-vercel; `ADAPTER=node npm run build` selects Node.
